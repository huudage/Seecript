# Seecript PRD · v2.0（功能更新版）

> **基线**：`Seecript/docs/PRD.md` v1.0（stage-21 对齐，**原文件保留不覆盖**）。
> **大修日期**：2026-09-23 · 方法论：prd-0to1-ai skill（迭代版适配：双看板 + 缺口追问 + 决策门）。

## 1. Executive Summary

Seecript 是一个把**爆款视频拆成可复用的结构骨架**，再把**用户自己的素材**对齐到该骨架上**重组**成新视频的 AI 创作工坊。这一定位 v2 不变；变的是**交互范式与 AI 边界**。

### 1.1 v2 三大变更主题

| 变更主题 | v1 现状 | v2 目标 | 驱动原则 |
|---|---|---|---|
| **交互范式全画布化** | 四轨时间线工作台（26 个 compose 组件）+ ⌘K 对话框主导改片 + 弹窗链换素材 | 结构画布：段落块 × 素材槽 × 连线；拖拽直接操纵为主，对话降级为兜底入口 | 剪辑是高度个性化场景，AI 做 copilot 辅助创作，不做唯一对话框入口主导创作 |
| **AI 主导时刻收编** | 3 处「一键全自动」：step1 生成内容轨 / step2→3 自动重写口播 / 出片前自动补缺 | 全部改为「AI 出初稿 / 出建议 → 人确认或拖改后生效」的盘内动作 | badcase 成本 = 错误的消费者 × 级联深度；AI 输出先给人看再进机器链 |
| **形态减重** | Remotion 子进程渲染包装 + T2V 主链路 + 知识库/步骤状态机/AB 对照等外围共 12 项 | ffmpeg 原生成片（xfade/ASS/drawtext/overlay/zoompan）+ WebAV 整体实时预览与轻量导出 + 补拍清单替代 T2V 主链路 + 外围裁剪 | 功能裁剪三问：真实需求与竞品 / 技术重量与 demo 难度 / badcase 必要性 |

### 1.2 不变项

用户问题（§2）、目标人群（§3）、「爆款结构 + 用户素材」差异化锚点（§4.3）、拆解 6 步流水线与确认门（F2）、「三层兜底」工程范式（Prompt / Router / Schema）——全部继承 v1。

## 2. Problem Statement

### 2.1–2.3 用户问题（继承 v1，不变）

短视频创作者（KOC / 品牌内容运营 / 独立编导）模仿爆款时只能复制表层，抓不到结构：**拆解、匹配、缺口、包装、改片**五个工作流断点没有任何主流工具串成一条链。痛点描述与证据链见 v1 PRD §2（逐字有效，不再重复）。

### 2.4 v1 形态自身的三个问题（v2 新增）

用户问题不变，但 v1 的**产品形态**在解决它的过程中长出了三个新问题：

| # | 问题 | 证据（代码锚点） | 后果 |
|---|---|---|---|
| **P-1 交互形态过重** | 素材落位无直接操纵：dnd-kit 仅做网格排序（`MaterialGrid.tsx:37-47`）；推荐落位只是卡片色条（`MaterialCard.tsx:135`）；换素材走 4-tab 弹窗（`SwapSourceDialog.tsx:23`）；改片靠 ⌘K 对话框 | 改片一个素材要经历「选中→弹窗→tab→确认」四步，或把意图翻译成一句话喂给对话框——**直接操纵感缺失**，AI 从辅助变成必经入口 | 用户在「自己会做的事」上也被迫过 AI，违背 copilot 宗旨 |
| **P-2 AI 主导时刻过多** | ①step1「生成内容轨」一键全自动（`Compose.tsx:1628`）②step2→3 自动重写口播+TTS（`Compose.tsx:1123-1177`）③出片前自动 copy 补缺（`Compose.tsx:1361-1464`） | 三处 AI 产物**未经确认直接进 Plan**，下游渲染直接消费 | AI 错误被机器链级联放大；用户对「成片为什么变成这样」失去解释权 |
| **P-3 技术栈过重** | Remotion 渲染包装（Node 子进程，OOM 风险）；Seedance T2V 30-90s 卡在用户主链路；上传理解/裁剪 badcase 高发 | v1 §9.3 风险表 + 实测 | demo 演示链路长、故障面大；自闭环要求下 Remotion 是最重的一环 |

### 2.5 市场证据：画布/无时间线范式（v2 新增）

| 范式 | 代表 | 对 v2 的验证点 |
|---|---|---|
| 场景卡家族 | Synthesia / Lumen5 | 「段落卡片 + 卡内分层」对小白创作者成立；Synthesia 卡内层（脚本/素材/样式同居一卡）与「块含其他轴」同构 |
| 文本式叙事 | Descript | 按叙事段落（非时间码）组织实拍素材的真实素材流，验证「段落优先」心智 |
| 节点画布 | Higgsfield / Runway / 2026 节点编辑器大众化浪潮 | 节点画布交互本身已被市场教育，不是首创风险 |
| 混合式 | Canva | 画布+时间线并存是过渡形态；纯画布（无时间线）对新手更友好 |

**结论**：「**节点画布 × 段落叙事 × 实拍素材重组**」在市场上无先例——这是 v2 的差异化锚点，不是跟随。

## 3. Target Users & Personas

三个 Persona（P0 训练营评委 / P1 视频创作者 / P2 自托管开发者）完整继承 v1 §3，仅更新两点：

- **P1 新增假设（待验证）**：P1「会基础剪映操作」意味着时间线心智已建立，但画布拖拽的学习成本**低于**时间线精调（市场证据 §2.5 支持新手友好性）；v2 上线后需用 P1 用户测试验证「无时间线」是否造成精修障碍。
- **P0 关注点更新**：可展示性从「四轨 + Remotion 预览」转为「结构画布 + 功能盘 + ffmpeg 原生渲染」——自研交互范式的展示价值高于第三方渲染管线。

## 4. Strategic Context

### 4.1 设计原则（v2 新增，全部功能的裁决框架）

**Copilot 三原则**（顺序即优先级）：

1. **AI 不做唯一入口**——每一个 AI 能力都必须存在画布上的直接操纵等价物（AI 能配口播，人也能双击块内层直接改文字；AI 能裁剪，人也能拖入出点）。
2. **AI 产物先确认后生效**——AI 初稿落到画布是半透明可拖改态；盘内动作走 diff 预览→应用；渲染前过确认清单。机器链只消费「人已确认」的产物。
3. **确定性环节用代码不用 LLM**——转场样式走 6 选 1 白名单、叙事顺序由连线结构决定、轮次收敛由 router 硬拦截。LLM 只做「需要判断力」的事。

**Badcase 成本公式**（功能去留的判断尺）：

> badcase 成本 = 错误的消费者 × 级联深度。AI 输出给人消费（报告/建议/贴纸）→ 人当场可校验，成本可控；AI 输出给机器消费（自动进 Plan→渲染）→ 错误级联放大到成片。

用户上传理解/裁剪 badcase 的解法是**改消费方式**（报告 + 建议 + 确认门），不是砍掉理解能力本身。

### 4.2 目标（OKR 更新）

| O · 拿到训练营第一梯队成绩 | KR | 相对 v1 变化 |
|---|---|---|
| KR1 基础闭环 25 分 | 4 页前端（Home / Library / Decompose / Compose·画布）+ 后端路由（裁剪后）全部跑通公网真链路 | 知识库页移除，5→4 页 |
| KR2 缺口处理 20 分 | 缺口三态可视化 + 四路补全：rerank / 字卡 / AIGC 图 / **补拍清单**；T2V 以盘内「AI 合成视频」单点保留（显式触发，不进主链路） | 补拍清单为新增路；T2V 出主链路（Q4 已决：单点保留） |
| KR3 可展示 20 分 | **结构画布**（段落块×素材槽×连线 + 手动切分）+ **功能盘**（鼠标跟随 copilot）+ **整体实时预览与导出**（WebAV）+ ffmpeg 原生成片 + SSE | 自研交互范式替换 Remotion 预览 |
| KR4 进阶 20 分 ≥16 | services/agent 维持 ≥6 个 + 功能盘局部改片（ComposeEditDiff 复用）+ 三层兜底范式维持 | agent 层基本不动，交互层重写 |

### 4.3 竞争景观（更新一行）

继承 v1 四类（通用剪辑 / 通用对话 AI / AI 视频生成 / 卡点模板库），新增：

| 类目 | 代表 | 与 Seecript 的差异 |
|---|---|---|
| 画布/节点编辑器 | Synthesia / Lumen5 / Descript / Higgsfield / Canva | 它们的节点是「场景模板/生成节点」，不消化**用户实拍素材**；「节点画布 × 段落叙事 × 实拍素材重组」无先例 |

**差异化锚点（更新）**：仍卡在「爆款结构 + 用户素材」中间抽象；v2 用画布范式把这个抽象**显性化**为可拖拽的空间结构——上游不抢生成、下游不抢剪辑，中间不撞任何先例。

### 4.4 Why now（更新）

- 节点画布编辑器 2026 年大众化（Higgsfield/Runway 教育了市场），交互范式教育成本已由先行者支付。
- copilot 范式（鼠标跟随功能盘、AI 出建议人拍板）在开发工具领域已被验证，迁移到创作工具是顺水推舟。
- 多模态 LLM 单次拆解 60s 视频能力成熟（继承 v1）。

## 5. Solution Overview

### 5.1 页面结构（5 页 → 4 页）

```
Home（项目导航）
  ↓
Library（样例选取 + 上传，输入域收窄：≤60s / 三类型白名单）
  ↓
Decompose（SSE 6 步流水线 → 结构报告 + 人工确认门）
  ↓
Compose · 结构画布（v2 核心：段落块×素材槽×连线 + 手动切分 + 功能盘 + PlanPlayer 块级/整体预览 + 总览条）
  ↓（渲染确认清单）
Render（ffmpeg 原生 · SSE 进度 → MP4）
```

### 5.2 关键功能（F1–F10，编号对齐 v1 便于 diff）

#### F1 · 样例库（Library）——微调

双 tab + 三分类筛选继承 v1。变化：上传入口校验收窄为「≤60s / marketing·editing·motion_graph 三类型白名单」（配合 U7），超域输入引导到系统样例。

#### F2 · 样例拆解（Decompose）——定位收窄

- 6 步 SSE 流水线（PySceneDetect → librosa → VAD → ASR → 帧打标 → 段落结构）**不变**。
- **产物定位收窄**：拆解结果不是「喂给机器的 ground truth」，而是**给人看的结构报告**——段落角色 / 镜头切分 / 主题，用户看完确认。
- **确认门维持**（v1 已实装，`Decompose.tsx:788-1017`）：draft 态 + ManifestEditor 手改 + 版本槽。拆解错了 → 人改，而不是下游 AI 连环猜。
- **输入域收窄**（U7）：≤60s、三类型白名单内。理由（三问）：①超出域的样例本就不是目标场景 ②60s 内 badcase 率可控 ③拆解耗时线性可控。

#### F3 · 结构画布（Storyboard Canvas）——v2 核心，全新

取代 v1 的四轨工作台 + 26 组件。心智模型是**结构故事板**（不是流程编排）：节点 = 叙事段落，不是函数。

**段落块（SectionBlock）容器规格**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `role` | `SectionRole`（4 枚举） | 开场 / 发展 / 高潮 / 收尾，块头色带标识 |
| `theme` | `str ≤ 20` | 该段讲什么（来自拆解/改编） |
| `slots` | `1..n` 素材槽 | 每槽可放：实拍视频 / AIGC 图 / 字卡 / 空槽 |
| `voiceover` | `str`（块内层） | 口播稿文本，人可双击直改 |
| `subtitle_spec` / `title_bar_spec` | 块内层 | 字幕与标题条样式，挂在该块时间轴内 |
| `in/out` | `ms`（每素材槽） | 入出点；盘内「AI 裁剪」建议 + 手动微调 |
| `duration` | 推导值 | 由各槽素材时长与倍速推导 |

**画布语法**：

| 元素 | 含义 | 交互 |
|---|---|---|
| **块（节点）** | 叙事段落容器，含块内层 | 拖动改位置；块头拖动重排叙事链 |
| **块内层** | 字幕 / 标题条 / 口播稿同居一卡，各带 **mini 时间条**（块内相对时间轴） | 文字直接编辑；时间条拖动调整起止（细节 Q6 开发期定） |
| **连线（边）** | 叙事顺序 + 转场载体 | 点击连线 → 6 风格白名单选择器（`TransitionStyle`，原生控件非 AI） |
| **背景层** | BGM 轨道 | 挂画布背景；BGM 从预设列表选（音频理解/燃点分析已裁剪 §8） |
| **成片总览条** | 画布底部常驻 | 按连线链序显示各块时长占比 + 总时长；拖动重排（同步更新连线）；补偿「无时间线」的时序感 |
| **块切分** | 实拍素材块按时间轴手动切分（一分为二，连线自动串联） | 选中块后块底边显示时间刻度，拖切分游标定切点（PlanPlayer 同步预览切点前后）；**边界规则：拥有其他轴（字幕/标题条/口播）的块不支持再切分**——切分会破坏内层与块时间轴的对齐，须先摘除内层（贴纸化使摘除便宜）；块内层无第二层时间轴，编辑粒度以 v1 step3 能力为上限 |
| **PlanPlayer** | 常驻角落；预览管线详见 F7 | 点任意块预览该块（含转场上下文 1s）；「播放整片」进入整体实时预览（WebAV，见 F7）；拖拽中的块即时反映到 plan_store |

**交互契约（F13 拍板）**：

- **拖拽 = 即时生效 + 撤销兜底**：任何画布操作（拖块 / 换槽素材 / 调连线）直接 `plan_store.replace`（新 plan_id 入撤销栈，⌘Z 一步回滚）。**确认门只留给 AI 动作**——人是权威源，人的操作不需要向自己确认。
- **AI 贴纸**：拆解建议（「建议特写」「参考 0:42」）、素材理解结果、缺口提示，以贴纸形式贴在块/槽上，一键摘除。

**技术选型**：React Flow（@xyflow/react）实现画布；块内层为自定义节点内部渲染。市场调研（F14）支持该范式。

#### F4 · 缺口与补拍（Gap & Shot Brief）——T2V 出主链路

缺口三态（ok / warn / miss）与检测逻辑继承 v1。补全四路重构：

| 动作 | 行为 | 变化 vs v1 |
|---|---|---|
| **rerank** | 从素材库重排候选 | 不变 |
| **copy 字卡** | outline 调参 → 渲染字卡 | 不变（入口收进功能盘空槽） |
| **aigc_image** | Seedream 文生图 | **降级定位**：封面 / 底图 / 静态特写（便宜、快、badcase 低） |
| **补拍清单（新增）** | shot brief：拍什么 / 多长 / 什么情绪 / 参考哪段 | **替代 T2V 主链路**：缺口优先引导用户自己拍，AI 出拍摄规格而非替拍 |
| **T2V（Seedance）** | 5-8s 生成短片 | **出主链路**（Q4 已决：demo 单点保留）：入口=盘内「AI 合成视频」动作，显式触发、不自动、不默认、不在缺口推荐顺位 |

**Why（三问）**：①缺口的真实需求是「这段有画面」——用户自己拍是质量最高、成本最低的路，AI 替拍是最后手段 ②T2V 30-90s 卡主链路、720p 单点故障 ③T2V badcase（生成内容与结构不符）由渲染直接消费，级联到成片。

#### F5 · 包装（Packaging）——收进画布

- 5 预设（minimalist / energetic / info_feed / dialogue / custom）与推荐 agent **保留**，入口收进功能盘（段落块 → 「包装」）。
- 落地载体变化：转场 → 连线样式；字幕/标题条 → 块内层；封面 → AIGC 图动作。不再有独立包装轨。
- 渲染侧由 Remotion 改为 ffmpeg 原生（F7 映射表）。

#### F6 · 功能盘（Copilot Dial）——v2 核心，全新

**Qoder 式鼠标跟随功能盘（2026-09-23 修订：中键唤盘，右键让位给撤销）**：中键（滚轮按下）任何对象 → 该对象锚定的动作盘跟随鼠标弹出；**右键 = 撤销上一步操作**（画布全域，配瞬时反馈贴纸；无可撤销时提示）。改用中键的原因：右键在画布上有原生 contextmenu 语义冲突，且撤销是高频动作，值得独占一个最顺手的键位。功能盘 = **tool 白名单的可视化**（盘上有什么 = 后端允许该锚点做什么，无隐藏能力；未接入的能力不出现，不摆灰置项），盘内含 AI 动作与结构动作两类。

**盘的开关契约**：中键唤出 / 重锚定；左键空白、Esc、盘内再中键、点击动作后、plan 变更（锚点引用作废）即收。

**盘内动作（按锚定对象分组，AI 8 + 结构 3）**：

| 锚定对象 | 动作 | 性质 | 复用底座 | 生效方式 |
|---|---|---|---|---|
| 实拍素材块 | **AI 理解**（打标/亮点/摘要 → 贴纸） | AI | 素材预处理已有 | 贴纸贴块上，一键摘除 |
| 实拍素材块 | **AI 裁剪**（建议入出点） | AI | `ComposeEditDiff`（apply=false） | diff 预览 → 人确认应用 |
| 空槽 / 画布空白 | **添加视频块**（空白实拍槽） | 结构 | 画布节点创建 | 即时生效（⌘Z 兜底） |
| 空槽 / 画布空白 | **生成字卡** | AI | copy outline agent | 调参 → 生成 |
| 空槽 / 画布空白 | **AIGC 补图** | AI | Seedream | 生成静态图/封面 |
| 空槽 / 画布空白 | **AI 合成视频**（T2V） | AI（demo 单点） | Seedance + t2v provider | 显式触发 → 生成视频块 |
| 空槽 / 画布空白 | **补拍清单** | AI | 新增 | shot brief 文档给人看 |
| 段落块 | **局部改片**（NL，作用域限该段） | AI | `compose_edit_agent` + step 域隔离 | diff → 应用 |
| 段落块 | **配口播**（生成/重写口播稿） | AI | copy 能力 | diff → 应用 |
| 段落块 | **包装**（该段预设/微调） | AI | packaging agent | 预览 → 应用 |
| 连线 / 块间 | **转场**（6 风格白名单） | 结构 | `TransitionStyle` 枚举 | 选择即生效（⌘Z 兜底） |

**盘外入口**：⌘K 全局命令 = **降级兜底**（保留给键盘党与画布空白处全局改片，不再是主入口）；**右键撤销**（画布手势层，走编辑撤销栈，与 ⌘Z 等价）。

**Why（AI 边界视角）**：功能盘把「AI 能做什么」从对话框的无限空间收敛为**锚定对象上的有限白名单**——用户看得见 AI 的边界，AI 越不了界；同时每个 AI 动作都有画布直接操纵等价物（4.1 原则 1）。T2V 收进盘内「AI 合成视频」= 白名单上的显式选项而非自动路径（Q4 拍板）。

#### F7 · 渲染与预览（Render & Preview）——ffmpeg 原生成片 + WebAV 实时预览，Remotion 移除

自闭环硬约束下的减重（U5）：成片渲染全部用 ffmpeg 原生 filter 实现，移除 Remotion Node 子进程；预览与导出按 Q3 拍板纳入 WebAV 浏览器端管线。

**预览管线（两级，Q3 拍板）**：

| 级别 | 形态 | 实现 |
|---|---|---|
| 块级预览 | PlanPlayer 点块即播（含转场上下文 1s）；切分游标同步预览切点前后 | 单素材 `<video>` 直播 |
| **整体实时预览** | 「播放整片」：按连线链序实时串播全片（素材顺序播放 + 转场近似 + 字幕/标题条叠加） | **WebAV** 浏览器端管线 |

**导出通道**：

| 通道 | 定位 | 实现 |
|---|---|---|
| 服务端 ffmpeg | **成片终态**（demo 主路径）：字幕字体精确、xfade 转场终态，MP4 落 `var/outputs/` | ffmpeg filter graph |
| 浏览器端导出 | 轻量快速导出（预览同管线落盘，占用户机器、免服务器渲染；P2 自托管/大流量兜底） | WebAV（与实时预览同管线，边际成本低） |

**ffmpeg 7 件映射表（替代 Remotion）**：

| v1 包装件（Remotion） | v2 ffmpeg 原生 |
|---|---|
| 转场 | `xfade` filter（6 风格 → xfade preset 映射表） |
| 字幕 | ASS 字幕轨（libass 渲染） |
| 标题条 | `drawtext` + box 背景 |
| 封面 / 贴纸 | `overlay` + 缩放定位 |
| 静图动效 | `zoompan`（Ken Burns） |
| keyframe_morph 变形 | **裁剪**（§8） |
| 透明 WebM 序列 | 不再需要（无子进程） |

主轨 concat 继承 v1。服务端渲染 SSE 三步进度（concat / overlay / mux）不变。

**前置步骤——渲染确认清单（U3 ③）**：点渲染后先弹确认清单（缺口 / 空槽 / 未定稿块逐项列出），用户逐项处理后才提交渲染。**未经人确认的 AI 产物不进渲染**（§6 Guardrail 红线）。

#### F8 · 知识库（Knowledge）——裁剪

页面 + profile 4 路由整体移除（三问：①偏好沉淀非本期真实需求，无用户验证 ②4 路由 + 页面维护成本 ③隐性规则注入不可解释、badcase 由渲染消费）。v1 的 KTBD 场景（跨项目偏好）留待有真实用户后重启。

#### F9 · 项目化隔离（Project）——简化

项目 CRUD + `var/projects/<id>/` 物理隔离**保留**。裁剪：步骤状态机（step commit 3 路由）移除——画布本身就是进度（块状态可见），不再需要显式状态字段。

#### F10 · AI 边界与收编（v2 新增总纲）

v1 的 3 处 AI 主导时刻（`Compose.tsx:1628 / 1123-1177 / 1361-1464`）收编方式：

| # | v1 行为 | v2 收编后 |
|---|---|---|
| ① | step1「生成内容轨」一键全自动 | **聊天确认结构保留（F17）**：clarify 多轮澄清（AI 问 → 用户选 → finalize）先行，确认结构后才生成；`plan_agent` 产物以**初稿模式**落到画布（半透明块 + 「AI 初稿」贴纸），用户拖改后点「定稿」——AI 搭台，人拆台 |
| ② | step2→3 自动重写口播 + TTS | 盘内**「配口播」**动作，人触发、diff 确认（TTS 配音整体裁剪 §8，口播以字幕呈现） |
| ③ | 出片前自动 copy 补缺 | **渲染确认清单**（F7 前置步骤），逐项人工处理 |

### 5.4 AI 边界矩阵（总账）

| AI 职责 | 触发方式 | 产物消费方式 | 人校验机制 |
|---|---|---|---|
| 样例理解（拆解） | Decompose 流水线 | 结构报告给人看 | 确认门（ManifestEditor） |

| 口播稿 | 盘内「配口播」 | 块内层文本 | diff 确认 |

## 7. User Stories & Requirements

> Epic 假设继承 v1 §7.1（链路型工坊 → 30 分钟产出结构对齐视频），v2 追加：**「用户在画布上的每一步都是自己直接操纵的，AI 只在用户点名时出现」**。

#### Epic-1 · 样例拆解（继承 + 收窄）

- **US-1.1**：作为 P1，上传样例后看到 6 步进度 → 拆解结果是**我能看懂、能改**的结构报告，不是黑盒。
  - **AC**：SSE 6 步；draft 态 + ManifestEditor 手改 + 保存确认门；≤60s/三类型白名单外输入被前置拦截并引导系统样例。
- **US-1.2**：作为 P1，拆错了我想改了再往下走。
  - **AC**：确认门内改段落角色 / 主题 / 镜头归属，保存后才允许进画布。

#### Epic-2 · 素材理解与落位（画布原生）

- **US-2.1**：作为 P1，我拖一个素材进某个槽，它就在那——不用弹窗、不用对话。
  - **AC**：画布拖放 → `plan_store.replace` 即时生效；⌘Z 回滚。
- **US-2.2**：作为 P1，我不确定素材适合哪段时才要 AI 帮忙。
  - **AC**：中键素材块 → 「AI 理解」出贴纸（推荐段落 / 亮点 / 摘要），贴纸可摘除；推荐不是默认行为。

#### Epic-3 · 结构画布（v2 核心）

- **US-3.1**：作为 P1，我要在一张画布上看清整条片子的结构并直接调整。
  - **AC**：段落块（role 色带 + theme + 槽）+ 连线（叙事顺序 + 转场）+ 底部总览条（时长占比 + 总长）；拖块重排同步更新连线。
- **US-3.2**：作为 P1，字幕、标题条、口播稿就在对应的段落里改，不要去全局轨道找。
  - **AC**：块内层三轴同居一卡，双击直改；各带 mini 时间条（Q6 细节开发期定）。
- **US-3.3**：作为 P1，我的每次拖拽立即生效，改错了 ⌘Z 一步回来。
  - **AC**：即时 replace + 撤销栈；不弹确认框（确认门只留给 AI 动作）。
- **US-3.4**：作为 P1，不想要时间线，但我要能感知成片时长并随时看全片。
  - **AC**：总览条实时显示链序时长分布；PlanPlayer「播放整片」进入整体实时预览（WebAV）；预览同管线可直接浏览器端导出，成片终态走服务端 ffmpeg。
- **US-3.5**：作为 P1，一个素材块太长，我要按时间轴把它切开分到两段。
  - **AC**：选中实拍块 → 块底边时间刻度拖切分游标（PlanPlayer 同步预览切点前后）→ 一分为二、连线自动串联；**拥有其他轴（字幕/标题条/口播）的块不可再切分**，须先摘除内层；块内层无第二层时间轴（编辑粒度以 v1 step3 能力为上限）。

#### Epic-4 · 缺口与补拍

- **US-4.1**：作为 P1，系统告诉我哪段缺画面，并给我**能执行的选择**，而不是替我生成完事。
  - **AC**：缺口三态贴纸/清单；空槽中键盘出三选：字卡 / AIGC 图 / 补拍清单（shot brief：拍什么/多长/情绪/参考段）。
- **US-4.2**：作为 P1，静态特写和封面走图（便宜快），别每次都重生成。
  - **AC**：`aigc_image` 定位封面/底图/静态特写；按 scene.duration 定格 mp4 继承 v1。

#### Epic-5 · 功能盘（v2 核心）

- **US-5.1**：作为 P1，我中键什么，就出现针对它的动作——盘上没有的能力就做不了。
  - **AC**：AI 动作 8 个 + 结构动作 3 个（添加视频块 / 转场）按锚定对象分组；盘 = tool 白名单可视化；右键 = 撤销上一步（配瞬时反馈贴纸）。
- **US-5.2**：作为 P1，AI 改我的东西前先给我看 diff。
  - **AC**：AI 裁剪 / 配口播 / 局部改片 / 包装全部 diff 预览 → 确认 → 应用；未确认不落 plan。
- **US-5.3**：作为 P1，我习惯键盘——⌘K 还在。
  - **AC**：⌘K 保留为全局兜底入口，能力同 v1（step 域隔离继承）。
- **US-5.4**：作为 P1，AI 的建议我想留就留、想扔就扔。
  - **AC**：贴纸一键摘除；diff 一键放弃。

#### Epic-6 · 包装（简化）

- **US-6.1**：作为 P1，我选个预设，整条片子的包装风格统一。
  - **AC**：盘内「包装」→ 5 预设；落地为连线转场 + 块内层字幕/标题条 + 封面图；ffmpeg 渲染。

#### Epic-7 · 渲染与产物

- **US-7.1**：作为 P1，出片前系统把「还没定的」列给我，我逐项处理，不会渲染出半成品。
  - **AC**：渲染确认清单（缺口 / 空槽 / 未定稿块）；0 未确认项才提交。
- **US-7.2**：作为 P1，渲染有进度，产物直接下载；等不了精渲时我可以在浏览器直接导出。
  - **AC**：服务端 SSE concat/overlay/mux 三步，MP4 落 `var/outputs/`；浏览器端 WebAV 导出（预览同管线）为快速通道。
- **US-7.3**：作为 P2，我不用装 Node 也能渲染。
  - **AC**：纯 ffmpeg，无 Remotion 子进程；依赖仅 Python + ffmpeg 二进制。

#### Epic-8 · AI 主导时刻收编（v2 新增）

- **US-8.1**：作为 P1，AI 给我的初稿是**可拖改的草稿**，不是既成事实。
  - **AC**：拆解后先走聊天确认结构（clarify 多轮：AI 问 → 用户选 → finalize，v1 能力保留）；确认后生成内容轨 → 画布半透明初稿 + 「AI 初稿」贴纸；拖改 → 「定稿」。
- **US-8.2**：作为 P1，口播是我想配的时候才配，不要自动替我重写。
  - **AC**：原 step2→3 自动重写口播移除；盘内「配口播」人触发。
- **US-8.3**：作为 P1，系统永远不背着我用 AI 填我的缺口。
  - **AC**：原出片前自动补缺移除；改走渲染确认清单。

### 边缘场景与约束

| 场景 | 处理 |
|---|---|
| 纯 BGM 无口播样例 | VAD 跳过 ASR（继承 v1） |
| 拖拽中断（鼠标脱靶） | React Flow 原生处理 + plan_store 原子替换 |
| 画布块数很多 | 分组折叠；性能阈值 50 块 < 3s（§6.2） |
| 白名单外输入（>60s / 其他类型） | Library 前置拦截 + 引导系统样例 |
| 画布上误删块 | ⌘Z 撤销栈 |
| LLM JSON 畸形 | `_extract_json` + 一次重试（继承三层兜底） |

### 9.3 风险与缓解（v2 新增为主）

| 风险 | 影响 | 缓解 |
|---|---|---|
| **画布学习成本**（无时间线对熟练创作者层级 +1） | P1 适应成本 | 市场证据（§2.5 小白友好）；总览条 + 块内层 mini 时间条补偿；P1 用户测试验证 |
| **精修层级 +1**（时间轴藏在块内层） | 微调多一次点击 | mini 时间条直接可拖（Q6）；高频精修入口盘内直达 |
| **xfade 多段串接性能**（转场数多时 filter graph 复杂） | 渲染耗时上升 | 分段渲染再 concat；≥10 转场样片纳入回归集 |
| **WebAV 预览 vs ffmpeg 成片一致性**（转场/字幕两端实现） | 预览与成片视觉差异 | 预览标注「近似」；关键样式（字幕字体/转场参数）两端用同一配置源；服务端 ffmpeg 为成片终态口径；渲染确认清单最后兜底 |
| **WebAV 滤镜/字幕兼容矩阵** | 整体预览部分样式缺失或丢帧 | Q3 拍板接受的成本；保底形态=素材顺序播放+DOM 叠加字幕；兼容矩阵在 PoC 阶段逐项验证 |
| **React Flow 大节点（块内层）性能** | 50+ 块卡顿 | 块折叠态/展开态；性能阈值进 §6.2 |
| **ffmpeg 字体环境**（drawtext/ASS 依赖系统字体） | 服务器渲染字样漂移 | 字体文件随部署包走，`fonts/` 目录显式声明 |
| **功能盘动作与后端 tool 白名单失同步** | 盘上能力与实际不符 | 盘 = schema 驱动（tool 白名单单一来源），CI 校验一致性 |
| Doubao 限流 / LLM JSON 漂移 | 盘内动作失败 | 三层兜底继承（mock + `_extract_json` + 重试） |
| 公网 demo 被恶意上传 | 磁盘膨胀 | ≤60s/三类型 + 200MB 双校验（继承） |
